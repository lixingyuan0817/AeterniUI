# AeterniUI

AeterniUI is a Blazor component library designed to provide a consistent UI across Blazor Server, Blazor WebAssembly, and Tauri + Blazor WebAssembly applications.

## Requirements

- .NET SDK 10.0 or a compatible .NET 10 SDK.
- Rust toolchain.
- Tauri CLI 2.x for desktop development.
- A platform WebView supported by Tauri.

The project uses .NET 10 packages and targets `net10.0`. Restore NuGet and Cargo dependencies on the new machine instead of copying generated output from the old machine.

## Projects

- `src/AeterniUI`: component library, including the built-in vendor-neutral `AeterniIcons` set used by the components themselves.
- `src/AeterniUI.Icons.FontAwesome`: optional Font Awesome Free 7.3.1 icon definitions, generated by `scripts/generate-fontawesome-icons.mjs`.
- `src/AeterniUI.Sample`: Blazor WebAssembly sample.
- `src-tauri`: Tauri desktop host.
- `docs/project-index.zh-CN.md`: project structure, entry points, startup and build command index.
- `docs/component-design-guidelines.zh-CN.md`: component development rules.
- `docs/current-features.zh-CN.md`: current implemented feature list.

## Start the Sample in Tauri

```bash
cd src-tauri
cargo tauri dev
```

This command publishes the Blazor sample through the configured `beforeDevCommand` into the repo-root `dist/` folder, then Tauri loads `dist/index.html` directly. There is no `dotnet watch` and no dev server; the UI is refreshed by rerunning `cargo tauri dev` or `scripts/sample-publish.sh`.

The repo-root `dist/` folder is regenerated by the script and is git-ignored; do not edit or commit it. If startup reports an issue, confirm `dist/index.html` exists (it is produced by the publish step). `bin`, `obj`, and `target` should not be copied between computers.

## Use the Library

Register the services in the application:

```csharp
builder.Services.AddAeterniUI();
```

Place the providers once in the root layout:

```razor
<ThemeProvider />
<DialogProvider />
@Body
```

The public API and component rules are documented in the files under `docs/`.

## Icons

Components render every internal glyph (check marks, chevrons, the rating star,
notice severity symbols and close buttons) through the core `Icon` component and
the built-in `AeterniIcons` set, so no icon vendor is required for the library
itself. Consumer icons come from an adapter package such as
`AeterniUI.Icons.FontAwesome`, which ships a curated Font Awesome Free 7.3.1 set
exposed as `FontAwesomeIcons.Solid.<Name>`, `FontAwesomeIcons.Categories` and
`FontAwesomeIcons.TryGet(name, out definition)`. The sample browses the whole set
at `/icons`.

`FontAwesomeIcons.cs` is generated from the official npm packages; edit the
manifest in `scripts/generate-fontawesome-icons.mjs` and rerun it instead of
hand-writing path data (the script needs Node and network access on first run;
the .NET build itself does not depend on either).

## Move to Another Computer

1. Copy or clone the source tree, excluding generated output and IDE metadata.
2. Install the required .NET SDK, Rust toolchain, and Tauri CLI.
3. Run `dotnet restore aeterni_ui.slnx`.
4. Run `cargo fetch --manifest-path src-tauri/Cargo.toml`.
5. Start with `cargo tauri dev` from `src-tauri`.
6. Open `AGENTS.md` before asking another coding agent to modify the project.

Machine-specific proxy settings belong in the new computer's shell or Agent configuration, not in the repository. Use the correctly named `HTTPS_PROXY` variable when configuring an HTTPS proxy.
